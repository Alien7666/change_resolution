## 情境 1：黑邊 — 先確認我的判斷對不對

**這一項最快，而且會影響你對其他情境的觀感。**

上次你說「切換後仍有黑邊」。快照顯示 2461W 的縮放是 `6`（長寬比／由顯示器執行），只有 Mi Monitor 是 `2`（全螢幕／GPU）。縮放設定是每台螢幕各自獨立的，你當初手動設的只有 Mi 那台。

**做什麼**

1. 啟動程式，設定成 **2461W** + 一個 4:3 模式（例如 `1440×1080 @ 60 Hz`）
2. 套用，確認出現黑邊
3. 按程式裡的 **GPU 縮放按鈕**
4. 看黑邊有沒有消失

**要回報**

- 按下縮放按鈕後黑邊消失了嗎
- 程式顯示的生效值是什麼（可能不等於它要求的值，那是驅動正規化，不是錯誤）
- 退出後快照裡 2461W 的縮放有沒有回到 `6`

**預期**：黑邊消失，縮放變 `2`，退出後回到 `6`。如果黑邊沒消失，那才是真的有問題。

## 情境 2：延遲倒數中手動取消

紀錄裡唯一明確標記「仍待測」的自動化行為。

**做什麼**

1. 設定一個你能隨手開關的程式當監看目標（例如 `notepad.exe`），延遲維持 3 秒
2. 套用模式，開啟 notepad，確認程式看到它在跑
3. 關掉 notepad，**在 3 秒內**按「恢復原始解析度」

**要回報**

- 是否立刻恢復（不是等倒數跑完）
- 倒數有沒有被取消 — 恢復之後再等 5 秒，畫面**不應該**再動一次
- 狀態列文字的變化

**預期**：立刻恢復，倒數取消，之後不再有第二次動作。

## 情境 4：放大方向（**先別做，等我通知**）

目前擋住的就是這一項。

上次 17:00 的實測重現了缺陷：Mi 還是 1920 寬的時候，XV 先移到 x=2560、2461W 移到 x=2556，然後 Windows 自己把 ZOWIE 從 x=−4 重排到 x=636。工具正確偵測到結果不符計畫、保留了待恢復狀態、也拒絕了後續操作，按「恢復原始解析度」有成功 — **但那是恢復路徑通過，不是放大通過。**

原因已經確認：套用順序是「每次套用決定一次」，不是「每台螢幕各自定序」。兩台相鄰的螢幕同向移動時，內側那台會先壓到外側那台身上，Windows 認為桌面無效就自己重排。

修正正在實作中（最外側先移、只排共線鄰居、回滾依實際套用順序反向）。**等我說可以再測這項**，現在測只會重現同樣的失敗。

## 測不了的項目

這兩項不是漏掉，是硬體條件不具備，會在發布說明裡標記為未驗證：

- **兩台相同型號的螢幕** — 你四台型號全不同，無法驗證「換接埠後拒絕錯誤對應」那條身分階梯的第二層
- **AMD / Intel 顯示卡** — 無法驗證非 NVIDIA 機器上縮放按鈕停用與提示文字

## 出問題怎麼辦

**畫面壞掉、滑鼠跑不到某台螢幕**：先從程式按「恢復原始解析度」。沒反應就直接關掉程式（工作管理員結束 `ResolutionTray.exe`），再用 Windows 顯示設定手動調回基線表的值。

**程式卡在「待恢復」狀態不讓你改設定**：那是刻意的 — 它知道桌面處於它造成但沒驗證成功的狀態，不肯在上面疊第二次寫入。按恢復即可解除。

**任何情況下都不要**用工作管理員強制結束來「跳過」一個卡住的還原，除非你已經準備好手動調回四台的模式與位置。
